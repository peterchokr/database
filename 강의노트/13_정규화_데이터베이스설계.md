# 13장. 정규화 (Normalization)와 데이터베이스 설계

## 📖 수업 개요

이 장에서는 효율적이고 무결성 있는 데이터베이스 설계의 기초인 정규화(Normalization)를 학습합니다. 
정규화는 데이터의 중복을 최소화하고 이상 현상(Anomaly)을 방지하여 데이터의 일관성을 유지하는 과정입니다.  
1차 정규형부터 3차 정규형, BCNF까지의 정규화 단계와 ER 다이어그램을 통한 데이터베이스 설계 방법, 그리고 실무에서의 정규화 적용을 다룹니다.  
이론적 기초를 바탕으로 실제 데이터베이스를 설계할 수 있는 능력을 개발하는 것이 목표입니다.

### 13.1 정규화 (Normalization)의 개념

**정규화**는 관계형 데이터베이스에서 데이터의 중복을 최소화하고 무결성을 유지하기 위해 데이터를 구조화하는 과정입니다.

**목적:**

• 중복 데이터 제거: 같은 정보가 여러 곳에 중복 저장되는 것을 방지하여 저장 공간을 절약합니다.   
• 이상 현상(Anomalies) 방지: 삽입, 갱신, 삭제 시 발생하는 데이터 불일치 문제를 해결합니다.   
&nbsp;&nbsp;&nbsp;&nbsp;• 삽입 이상: 데이터를 넣을 때 불필요한 정보도 함께 삽입해야 하는 문제   
&nbsp;&nbsp;&nbsp;&nbsp;• 갱신 이상: 중복된 데이터 중 일부만 수정되어 데이터가 일치하지 않게 되는 문제   
&nbsp;&nbsp;&nbsp;&nbsp;• 삭제 이상: 특정 데이터를 삭제할 때 의도하지 않은 다른 정보까지 함께 삭제되는 문제   
• 유연성 및 무결성 향상: 데이터 구조가 체계적으로 변경되어 확장성이 좋아집니다.   
  

---

### **함수 종속성**
속성 간의 종속 관계

**표기:** X → Y (X가 결정되면 Y도 유일하게 결정됨)

**예시:**

- 학번 → 학생명, 학과, 학년
- 사원번호 → 사원명, 부서, 급여

**완전 함수 종속:**

- Y가 X 전체에 종속 (X의 일부에는 종속되지 않음)

**부분 함수 종속:**

- Y가 X의 일부에만 종속 (불바람직)

**이행 함수 종속:**

- X → Y, Y → Z이면 X → Z (이를 제거하는 것이 3NF의 목표)

### 13.2 정규화 전: 초기 테이블 (학습 교재 수강 테이블)

이 테이블은 학번, 이름, 과목명, 교재, 강의실, 수강료 정보를 담고 있으며, 기본키(PK)는 복합키인 **[학번, 과목명]** 입니다.

| 학번 (PK) | 이름   | 과목명 (PK)            | 교재           | 강의실 | 수강료  |
| :-------- | :----- | :--------------------- | :------------- | :----- | :------ |
| 1001      | 김철수 | 데이터베이스, 알고리즘 | SQL 정석, Java | 301호  | 100,000 |
| 1002      | 이영희 | 데이터베이스           | SQL 정석       | 301호  | 120,000 |

### 13.3 1차 정규형 (1NF)

**1NF의 조건:**

- 모든 컬럼의 값은 **원자값(Atom, 더 이상 쪼갤 수 없는 단일 값)** 이어야 합니다.

* **문제점:** '김철수' 학생의 과목명과 교재 컬럼에 여러 개의 값이 쉼표(,)로 구분되어 들어가 있습니다.
* **해결:** 데이터를 분리하여 하나의 칸에 하나의 값만 들어가도록 펼칩니다.

### [1NF 만족 테이블]

| 학번 (PK)      | 이름   | 과목명 (PK)            | 교재     | 강의실 | 수강료  |
| :------------- | :----- | :--------------------- | :------- | :----- | :------ |
| **1001** | 김철수 | **데이터베이스** | SQL 정석 | 301호  | 100,000 |
| **1001** | 김철수 | **알고리즘**     | Java     | 302호  | 150,000 |
| **1002** | 이영희 | **데이터베이스** | SQL 정석 | 301호  | 120,000 |

---

### 13.4 2차 정규형 (2NF)

**2NF의 조건:**

- 제1정규형을 만족하고, 기본키의 **부분 함수 종속을 제거**합니다(완전 함수 종속 만족).

* **문제점:** 기본키가 **[학번, 과목명]** 인 복합키입니다. 하지만 '이름'은 **[학번]** 에만 종속되며, **[과목명]** 과는 상관이 없습니다.
* **해결:** [학번]에만 종속되는 데이터(이름)를 별도 테이블로 분리합니다.

### [2NF 분리 후: 학생 테이블]

| 학번 (PK) | 이름   |
| :-------- | :----- |
| 1001      | 김철수 |
| 1002      | 이영희 |

### [2NF 분리 후: 수강 강좌 테이블]

*기본키는 여전히 [학번, 과목명] 복합키입니다.*

| 학번 (PK) | 과목명 (PK)  | 교재     | 강의실 | 수강료  |
| :-------- | :----------- | :------- | :----- | :------ |
| 1001      | 데이터베이스 | SQL 정석 | 301호  | 100,000 |
| 1001      | 알고리즘     | Java     | 302호  | 150,000 |
| 1002      | 데이터베이스 | SQL 정석 | 301호  | 120,000 |

---

### 13.5 3차 정규형 (3NF)

**3NF의 조건:**

- 제2정규형을 만족하고, 기본키를 제외한 일반 속성들 간의 **이행적 함수 종속을 제거**합니다.(A → B 이고 B → C 이면 A → C 인 관계 제거)
  

* **문제점:** 위 수강 강좌 테이블에서 `[학번, 과목명] → 과목명 → 교재` 관계가 성립합니다. 즉, 교재는 기본키가 아니라 **일반 컬럼인 '과목명'에 종속**되어 있습니다. (과목이 '데이터베이스'면 교재는 무조건 'SQL 정석')
* **해결:** 일반 컬럼 간의 종속 관계를 가진 '과목명'과 '교재'를 별도 테이블로 분리합니다.

### [3NF 분리 후: 학생 테이블] (변동 없음)

### [3NF 분리 후: 수강 테이블]

| 학번 (PK) | 과목명 (PK)  | 강의실 | 수강료  |
| :-------- | :----------- | :----- | :------ |
| 1001      | 데이터베이스 | 301호  | 100,000 |
| 1001      | 알고리즘     | 302호  | 150,000 |
| 1002      | 데이터베이스 | 301호  | 120,000 |

### [3NF 분리 후: 과목 교재 테이블]

| 과목명 (PK)  | 교재     |
| :----------- | :------- |
| 데이터베이스 | SQL 정석 |
| 알고리즘     | Java     |

일반적으로 제3 정규화까지만 진행하고 이 이상은 진행하지 않는다.

### 13.6 BCNF (Boyce-Codd Normal Form)

**BCNF의 조건:**

- 제3정규형을 만족하고, **모든 결정자가 후보키**여야 합니다.

* **이해를 돕기 위한 상황 변경:** 위 `수강 테이블`에서 **"강의실(일반 컬럼)마다 담당 교수가 단 1명만 존재하고, 교수는 하나의 과목만 개설할 수 있다"** 는 새로운 규칙이 있다고 가정해 봅시다.
* **문제점:** 기본키가 **[학번, 과목명]** 일 때, `강의실 → 과목명`이라는 종속 관계가 성립합니다. 강의실(결정자)이 과목명을 결정하지만, **강의실은 후보키가 아닙니다.**
* **해결:** 후보키가 아니면서 결정자 노릇을 하는 '강의실'을 기준으로 테이블을 쪼갭니다.

### [BCNF 분리 후: 수강 신청 테이블]

| 학번 (PK) | 강의실 (PK) | 수강료  |
| :-------- | :---------- | :------ |
| 1001      | 301호       | 100,000 |
| 1001      | 302호       | 150,000 |
| 1002      | 301호       | 120,000 |

### [BCNF 분리 후: 강의실 배정 테이블]

| 강의실 (PK) | 과목명       |
| :---------- | :----------- |
| 301호       | 데이터베이스 |
| 302호       | 알고리즘     |

### 13.7 ER 다이어그램 (Entity-Relationship Diagram)

**ER 다이어그램**은 데이터베이스를 설계할 때 데이터 구조와 이들의 관계를 시각적으로 표현하기 위해 사용하는 도구입니다.

**ER 다이어그램의 3가지 핵심 요소:**

- **엔티티 (Entity):** • 데이터로 관리하고자 하는 대상 (예: 학생, 과목, 강의실) -> 직사각형으로 표기
- **속성 (Attribute):** • 개체가 가지는 세부 정보 (예: 학번, 이름, 수강료) -> 타원 또는 테이블 내부 텍스트로 표기
- **관계 (Relationship):** • 개체와 개체 간의 연관성 (예: 학생이 과목을 '수강'한다) -> 마름모 또는 선(Line)으로 표기


**카디널리티 (Cardinality):**

- 1:1 (일대일): 한 명의 학생은 하나의 학번
- 1:N (일대다): 한 명의 교수는 여러 강의
- M:N (다대다): 학생은 여러 강의, 강의는 여러 학생

###  정규화 결과를 반영한 ER 데이터 모델 구조
앞선 정규화(1NF ~ BCNF) 과정을 마친 최종 테이블들의 관계를 표기법에 맞춰 도식화하면 다음과 같은 뼈대를 가집니다.
```
  [학생] (1) -----------------------< (N) [수강 신청]
                                              |
                                              | (N)
                                              |
                                              | (1)
  [과목 교재] (1) >------------------ (N) [강의실 배정]
```
